## O problema

<Draft title="Por que importa (do currículo)">
Duas requisições simultâneas reduzindo o mesmo estoque causam *overselling*. A API precisa de uma estratégia explícita.

Comece com o problema que o conceito resolve e uma analogia do mundo real.
</Draft>

## O conceito

<Draft title="Tópicos previstos">
- *Lost update*
- `@Version` e `OptimisticLockException` → 409 na API
- *Lock* pessimista (`@Lock(PESSIMISTIC_WRITE)`, `SELECT ... FOR UPDATE`, `SKIP LOCKED`)
- Atualização atômica (`UPDATE ... SET qtd = qtd - :n WHERE qtd >= :n`)
- Como escolher; impacto em *retries*
- Preparação para `ETag`/`If-Match` (20.03)
</Draft>
